# Club Membership Registration

A full-stack web app where students register for school clubs. A React form sends the data through Axios to an Express API, which validates it and saves it in Firebase Firestore. Registered members appear as membership cards that can be searched, filtered by club, and removed.

## Tech stack

- **Client:** React, TypeScript, Vite, Axios
- **Server:** Node.js, Express, CORS, dotenv
- **Database:** Firebase Firestore (through the `firebase-admin` SDK)

## Features

- Controlled form with one state object and one `handleChange` function
- Six input types: text, email, select, radio buttons, textarea, checkbox
- Per-field error messages, validated on the client and again on the server
- Members load with `useEffect` through a custom `useFetch` hook, with loading and error states
- Duplicate protection: the same email cannot join the same club twice (409)
- Delete a member from the interface
- Responsive layout for phone and desktop

## Setup

You need Node.js 18 or newer and a Firebase account.

### 1. Create the Firestore database

1. In the [Firebase console](https://console.firebase.google.com), create a project.
2. Open **Build > Firestore Database** and click **Create database**.
3. Open **Project settings > Service accounts** and click **Generate new private key**.
4. Save the downloaded file as `server/serviceAccountKey.json`. It is listed in `.gitignore`. Never commit it.

The `members` collection is created automatically when the first member is saved.

### 2. Run the server

```bash
cd server
npm install
cp .env.example .env     # on Windows: copy .env.example .env
npm run seed             # optional: adds 3 sample members
npm run dev              # or: npm start
```

The API runs on http://localhost:3000 (or the `PORT` in `.env`).

### 3. Run the client

```bash
cd client
npm install
cp .env.example .env     # on Windows: copy .env.example .env
npm run dev
```

Open http://localhost:5173.

### Environment variables

| File | Variable | Purpose |
| --- | --- | --- |
| `server/.env` | `PORT` | Port for the API (default 3000) |
| `server/.env` | `CLIENT_ORIGIN` | Origin allowed by CORS (the Vite address) |
| `server/.env` | `FIREBASE_SERVICE_ACCOUNT_PATH` | Path to the service account key file |
| `client/.env` | `VITE_API_URL` | Base URL used by the shared Axios instance |

## Data model

Collection `members` (one document per registration, id generated by Firestore):

| Field | Type | Notes |
| --- | --- | --- |
| `member_name` | string | required, 2 to 100 characters |
| `email` | string | required, valid format, stored in lowercase |
| `club` | string | one of the clubs in `validate.js` |
| `year_level` | string | `1st Year` to `4th Year` |
| `interests` | string | required, at least 5 characters |
| `agreed_to_terms` | boolean | must be `true` |
| `created_at` | timestamp | set by the server |

## API endpoints

Base path: `/api/members`

| Method | Path | Purpose | Status codes |
| --- | --- | --- | --- |
| GET | `/api/members` | List members (optional `?search=` and `?club=`) | 200 |
| GET | `/api/members/:id` | Get one member | 200, 404 |
| POST | `/api/members` | Register a member | 201, 400, 409 |
| DELETE | `/api/members/:id` | Remove a member | 200, 404 |

Example error response (400):

```json
{
  "message": "Please fix the highlighted fields.",
  "errors": { "email": "Enter a valid email address." }
}
```

- Search and filter using query strings on the API (`?search=` and `?club=`)

## Known issues

- Firestore has no unique constraint, so the duplicate check (same email and club) is a query before the insert. Two identical requests sent at the exact same moment could both pass.
- Search runs in the server after loading the club's documents, which is fine for a school-sized collection but would not scale to very large ones.
